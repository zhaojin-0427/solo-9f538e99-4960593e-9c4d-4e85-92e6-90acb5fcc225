# 科研支出万元公示

高校财务把科研支出按整数万元公示：上传“院系 × 支出科目”的 CSV，系统生成一张
**横加、竖加都与表内小计及总计吻合**的万元公示表，并支持按所见版锁定院系行、
带锁定约束的底表更正。

## 功能与业务规则

- **底表**：CSV 首行表头，第一格留空/“院系”，其后为支出科目；首列为院系名。
  最多 20 行、10 列，金额为非负整数元（UTF-8，不接受小数/千分位/负号）。
- **取整**：每格与每行/列小计可向上或向下取整到万元；总计四舍五入（.5 向上）。
  求解不是逐格独立取整，而是用带下界的可行流同时满足：每格合法取整、行小计合法、
  列小计合法、总计精确、且表内横竖加平。无可行解时**拒绝保存**，原表不变。
- **锁定**：财务按页面当前所见版锁定某院系行，保存锁定时的公示单元格与行小计。
  提交的版号过期会提示“版号已过期，请刷新”并拒绝。
- **留档**：每次锁定在同一事务里同步留档（原科目、万元公示值、行小计、当时的底表元金额），
  任一方失败则锁定与留档都不生效、版号不变。留档页 `/archive` 可按院系名称与锁定时
  所见版号查询；重新导入 CSV 照常清空当前锁定，但旧档保留可查，后续更正或重启不改旧档。
  从旧版本升级时，启动会为仍在的锁定补建留档：仅当版号与锁定记录能确认该行锁定后
  底表从未更正，才用现有底表补记元金额；证据不足时保留原公示数字，元金额标为「未留存」。
- **更正**：沿用原行/列定义修改底表；锁定行的公示值与小计保持锁定原值。
  更正会按**最新**锁定记录重算。核算在写事务外进行，期间其他请求仍可锁定；
  提交时用底表版号 + 锁定快照做乐观校验，发现新锁定则按最新锁定重算重试。
  成功则底表与公示表在同一事务内一起生效；无解或保存失败则两表都保持原样。

示例底表见 `sample.csv`。

## 本地运行

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python run.py            # http://127.0.0.1:8000
```

数据默认写入 `data/finance.sqlite3`，可用 `DB_PATH` 覆盖。

## Docker Compose 启动

```bash
docker compose up --build -d
# 浏览器打开 http://localhost:8000
docker compose down
```

SQLite 数据保存在命名卷 `finance-data` 中。生产部署请通过环境变量设置 `SECRET_KEY`。

## 测试

```bash
python -m pytest -q
```

测试覆盖：
- 取整求解器与暴力枚举逐例比对（含锁定行与无解）；
- 渲染后的页面按页面上真实数字复算横加/竖加；
- CSV 校验（维度、重复、非整数、超大）；
- 按所见版锁定、过期拒绝、算表期间仍可锁定；
- 更正保持锁定原值、无解更正回滚、保存失败回滚；
- 交错提交：算表期间新锁定 → 按最新锁定重算；新锁定导致无解 → 更正不落库；
- 反复抢占导致重试耗尽 → 提示刷新且底表不变；
- 留档：锁定同步留档（含当时元金额）、留档失败则锁定与版号一起回滚、
  两次锁定之间的更正不改旧档、换表后旧档按原名称与版号可查、
  旧库迁移补建（无更正补记元金额 / 有更正标「未留存」）、迁移幂等且重启不改旧档。

## 已知限制

- SQLite 单库通过 `BEGIN IMMEDIATE` 串行化写事务，已用 2 worker gunicorn 验证；
  如需多主机横向扩展应换用 Postgres 等数据库。
- 更正按底表版号做乐观校验：他人先更正后，你的页面提示刷新并丢弃旧底表上的输入。
- 未提供解锁功能（需求未要求）；重新导入 CSV 替换底表会清空全部锁定记录，
  但锁定留档保留，可在留档页按原院系名称与版号查询。
- 旧库升级时补建留档的元金额依据「版号 + 锁定记录」推断：锁定之后若发生过更正，
  无法还原当时的元金额，该档元金额标为「未留存」，公示数字仍以锁定原值为准。
- 更正时锁定行沿用原公示值，即使该行底表金额变化后不再满足“本行上下取整”也保持原值；
  这是“锁定行保持原值”的直接结果，页面会照常提示核对状态。
- 本开发环境没有 Docker，`compose.yaml` 只做了 YAML 解析校验、Dockerfile 未实际构建；
  同一命令（gunicorn + 持久化 DB_PATH）已在本机直接验证。
